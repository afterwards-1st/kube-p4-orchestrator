# 可视化面板（dashboard）开发记录

开发日期：2026-10-28。配套代码：`dashboard/index.html`（单文件）。
本文档记录需求定位、架构决策、功能清单、验证过程与后续优化方向。

## 1. 需求与定位

为项目补一个"能看"的界面：展示当前 Worker 状态、调度结果与数据面转发效果，
**动态更新**，界面饱满。定位与约束：

- **零依赖、零构建**：单文件 HTML/CSS/JS，无 CDN、无 npm、无打包步骤——
  离线实验室环境直接可用，也便于整体替换或删除（用户后续要取舍）。
- **双模式**：实时模式消费真实 receiver 数据；演示模式本地仿真，
  没有集群也能全速运行——面试投屏不依赖环境。
- **前端独立成目录**：`dashboard/` 与 `app/` 解耦，receiver 只负责读取和伺服，
  删除 `dashboard/` 目录不影响任何指标功能（自动回落占位页）。

## 2. 架构与接入方式

~~~
dashboard/index.html        单文件面板（HTML + CSS + 原生 JS + Canvas）
        ↑ 每次请求动态读取
app/metrics_receiver.py     GET /dashboard 与 GET / 返回面板；/v1/backends、/health 不变
        ↑ 同源 fetch（无 CORS 问题），2 秒轮询，Token 经 X-Metrics-Token 头
浏览器（LIVE）                或 本地仿真（DEMO，500ms 一拍）
~~~

接入要点：

- 面板与 receiver 同源，天然绕开 CORS；Token 只存浏览器 localStorage，
  页面顶栏输入一次即可。
- `make_http_handler(store, token="", dashboard_html=None)`：`dashboard_html`
  为 None 时**每请求动态读文件**（开发期改面板刷新即生效）；传入字符串则固定
  返回（测试注入用）。签名向后兼容，旧测试零改动。
- P4 动画、走势图全部手绘 Canvas，不引图表库——体积与依赖都为零。

| 区域 | 内容 | 动态性 |

## 4. 调度算法复刻（关键正确性说明）

面板内置的调度器是 `app/policies/completion_time_scheduler.py` 的 **JS 同口径复刻**：

- 可行子集全枚举（`covers` 容量校验）→ 每个子集 `_resource_allocations`
  的主资源贪心分配 → 按分配 CPU 比例折减服务速率 → **最大余数法**分任务 →
  排队 + 网络时延 + 计算 + **批次等待修正**（`count % batch_size != 0` 时加超时）→
  以 (makespan, 总耗时, 节点数, id 序列) 元组序取最优。
- 已知语义（与 Python 一致，非 bug）：需求小于单节点容量时，主资源全部分配给
  子集内第一个节点，其余节点速率趋零、分不到任务，因此**小需求选单节点是最优解**；
  需求超过单节点容量（如 CPU 24 核）才会跨节点分配。演示时用大需求展示多节点效果。
- 指标假设在页面上明示：服务速率 100 任务/秒、网络时延 5ms、批大小 16、
  批超时 50ms、排队深度取实时值。

## 5. 验证记录（全部通过）

| 验证项 | 结果 |
| --- | --- |
| Python 单元测试（含新增 `tests/test_dashboard_route.py`：路由 200/text-html/注入/文件读取） | 89 项全部通过 |
| 冒烟脚本 `agent/tests/smoke_local.sh` | 含 dashboard 路由断言，全部通过 |
| 浏览器实测（ZCode 内置浏览器，1440×900）：演示模式 | 6 Worker 全部 FRESH，KPI/走势图/内存条/事件日志实时跳动，P4 报文动画与到达闪烁正常 |
| 浏览器实测：调度模拟器 | 24 任务/24 核需求 → 218(8)/227(8)/228(8)，makespan 145ms，枚举 42 个子集（63 − 不可行的 21），选中卡片高亮 + 日志联动 |
| 浏览器实测：实时模式 | LIVE 徽标，仅显示真实 Worker 216/217（CPU 0.4%、内存 17.2 MiB、来源 cgroup-v2），P4 视图只画真实节点 |

实测中发现并修复的两个问题：

1. **模式切换残留**：演示模式创建的 Worker 卡片切到实时模式后残留为冻结假卡片 →
   增加 `resetWorkers()`，切换模式时清空卡片与方案状态。
2. **面板更新需要重启 receiver**：原先 handler 创建时缓存 HTML → 改为每请求
   动态读取，编辑面板后浏览器刷新即生效（`dashboard_html` 注入语义不变）。

另修正一处算法复刻偏差：子集比较原用字符串拼接序，`9.0` 与 `10.0` 会误判，
改为与 Python 元组序一致的数值逐位比较（`cmpScore`）。

## 6. 使用方式

~~~
# 实时模式：启动 receiver 后浏览器打开
python -m app.metrics_receiver          # 默认 HTTP 8080
# 浏览器访问 http://<receiver地址>:8080/dashboard（或 /）

# 演示模式：直接双击打开 dashboard/index.html 也可以（无集群环境）
~~~

集群内访问：receiver Service 的 http 端口（8080）即可打开面板；
Token 在页面顶栏输入，保存在浏览器本地。

## 7. 后续优化方向（留给取舍）

- **数据面**：调度结果目前是前端复刻模拟；可让 controller 把真实 plan POST 给
  receiver（新增只读端点），面板切换为展示真实调度决策。
- **推送**：2s 轮换 WebSocket/SSE，进一步降低延迟与空轮询。
- **工程化**：需要组件化时再拆分 CSS/JS 并引入构建链（当前刻意单文件）；
  图表如需升级可换 uPlot/Chart.js（代价是引入依赖）。
- **鉴权**：面板本身不鉴权（与 /health 同级）；如需保护可复用 Token 或加 Ingress 层控制。
- **可观测**：KPI 可加历史聚合（如 5 分钟窗口 P99 排队），走势图支持多指标切换。
